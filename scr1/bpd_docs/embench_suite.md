# Embench-IoT suite для оценки предсказателя SCR1


## 1. Метод

- verilator, `CFG=RV32IMC_MAX`, rv32imc, 
- **Метрика предсказателя:** циклы при предсказателе ON (BTB 256 + BTFN + BHT 1024×2b + RAS 4) против **No-BPU**
- Интеграция: `sim/tests/benchmarks/embench_common/` (общий beebsc/main/support через
  VPATH) + папка на бенч; watchdog tb 500M циклов

## 3. Выводы

1. **Агрегат predictor-only: −5.38 % (очередь=2), −6.32 % (очередь=4)** на 16 бенчах.
   Предсказатель конвертируется лучше на очереди=4
2. **MPKI не равно выигрышу по циклам.** `ud` имеет MPKI 45.8, но лишь
   −0.99 % - compute-bound (soft-float), промахи спрятаны за исполнением.
   `tarfind` при MPKI 3.0 даёт **−18.4 %** — call-heavy код, где RAS и ранний
   steer сильно экономят.
3. Наибольшая польза - на call-heavy / цикло-branchy коде (tarfind, wikisort,
   statemate, slre, huffbench); наименьшая - compute-bound (matmult, ud) и
   слабо-ветвящихся (sha256, crc32).
